# Private names the Pydantic AI planner path relies on

The planner path is `agent/` (the agent, its model and client, the entry) and `node/` (the planner node of a Studio turn). This inventory covers google-adk 2.13.0, pydantic-ai-slim 2.66.0 and google-genai 2.34.0. A name is private if it starts with an underscore, lives in a module whose name does, or is absent from the library's documented API. For Pydantic AI "documented" means the API pages and guides at ai.pydantic.dev; for ADK it means the API reference at google.github.io/adk-docs. Both sites were fetched; neither page states the release it describes, so "documented" means documented now, not necessarily in the pinned version.

Totals: 4 ADK rows (3 private names called, 1 named in a docstring only), 15 Pydantic AI rows, 12 harness-internal names and 4 harness behaviours the path mirrors. Six Pydantic AI rows have no public alternative: `GoogleModel._build_content_and_config`, the merge exception on differing `instructions`, the unknown-tool answer, the empty-response ending, the `RunContext.messages` layout and the span timing. Each is pinned.

`private-names/test_pins.py` holds the pin named in the last column of each Pydantic AI row that has one. It needs only `pydantic-ai-slim[google]`, google-genai and OpenTelemetry, runs in under a second and sends nothing over the network: the fake client's `base_url` is a closed local port and its `generate_content` refuses, so a path that stops streaming fails.

## Pinned against 2.64.0 and 2.66.0

`test_pins.py` has 14 tests. Under pydantic-ai-slim 2.66.0 and 2.64.0, with the same environment otherwise, all 14 pass. The agent (18 tests), node (24) and node-hard (57) suites also pass under both. Nothing in the prototype broke between the two versions, so no pin caught a change and none failed to catch one.

The installed trees differ in many files. Those that touch the path, and what watches each:

- `Model.prepare_messages` gains a note after user text that opens `<context>` or `<context_diff>` in conversations with append-mode instructions. The planner has none. The typed `<context>` text in the verbatim-request pin passes under both.
- `GoogleModel._build_http_options` adds an `X-Server-Timeout` header when the google-genai client has an HTTP timeout. The planner's client sets retry options and no timeout, so no header is sent. No pin covers it; a client with a timeout would send a header ADK does not, and the request comparison in `agent/test_parity.py` would list it.
- `GoogleModel`'s streaming parser moves tool-call deltas and tool responses into `handle_tool_call_delta_events` and `_handle_tool_response`. Every pin that streams a function call reads them back.
- `Instrumentation` gains `current_model_request_span`. The span pin passes under both.
- `Model._run_scope` is new and `WrapperModel` forwards it. `PlannerModel` inherits the forwarding. No pin.
- The content-filter message moves to `_content_filter.content_filter_message` and gains the refusal text. The planner logs the message and branches on the exception type. No pin.
- `sanitize_messages` and the conversation store are new and not used.
- `_merge_consecutive_messages` keeps its rule; the merge pin passes under both.

To check that the pins can fail, six perturbations of 2.66.0 were run through a pytest plugin outside the repository. Deleting `GoogleModel._build_content_and_config` fails all 14 tests. Making `_merge_consecutive_messages` return its input fails the merge control. Making it ignore `instructions` fails the two-contents row and the verbatim-request pin. Silencing `_warn_on_cached_content_strips` fails the warning pin. Dropping `supports_inline_system_prompts` from the profile fails the verbatim-request pin on the added `<system>` sentence. Rewording `Unknown tool name` fails the unknown-tool pin. The thought-signature, retry-accounting, empty-response, context-layout, stop-node and span pins have not been shown failing under a library perturbation; each asserts a concrete value, so a changed value fails it.

## Not confirmed

- The Pydantic AI docs do not state their release, so a row marked "not documented" holds for the pages as fetched on 2026-11-10, not for the pinned 2.66.0 in particular.
- `ModelRequestNode.request` could not be found in the docs.
- `HttpOptions(httpx_async_client=...)` as a way to replace the client hook was checked only for its existence.
- The `process_llm_request(tool_context=None)` route was checked on the three planner tools of this checkout, not on every ADK tool type.
