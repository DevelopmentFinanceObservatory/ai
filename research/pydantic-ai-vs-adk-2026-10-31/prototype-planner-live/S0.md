# Planner tool bodies on `PlannerCall`

The planner's tool bodies read their call through `planner.call.PlannerCall` and end the run through an `EndRun` callable. `planner.agent` wraps them as ADK function tools. The bodies and the helpers they call live in modules that import nothing from `google.adk`.

## The neutral signature

```python
type EndRun = Callable[[], None]

ask_user(call: PlannerCall, end_run: EndRun, *, message, candidates, options, recommended_spec_id, rationale)
propose(call, proposal: Proposal, *, question_fixed, reads_user_words)
propose_with_reads(call, draft: Callable[[], dict], *, surface)
propose_and_translate(call, end_run, *, arguments, draft, translate, surface)
reject(call)
ready_and_end(answer, call, end_run)
read_skill_page(surface, tool, arguments, *, call, path)
```

`PlannerCall` carries `state`, `call_id`, `steps()` and `response_calls()`, which is all the bodies read. The end-of-run signal is a callable beside `PlannerCall`. Only three tools end a run, and a framework without a skip flag can supply any mechanism (the Pydantic AI path stops `Agent.iter` before the next request).

`draft` is the proposal made once, as a zero-argument callable. `propose_plan` keeps its `= []` defaults, so `Proposal` receives lists where `Proposal`'s own defaults are tuples, and `submission.service` tests `isinstance(raw, list)` on `evidence_requirements`. Passing the adapter's own call as `draft` keeps that value exactly.

## What stayed ADK-only

- `AdkCall` and `_session_steps`: the only reader of ADK `Event`s.
- The tool functions in `build_planner_tools`, `ask_user_question` and `build_skill_tools`. ADK builds each declaration from the function's name, signature and docstring, and from `functools.wraps` for the translating and reading variants, so those functions carry them. Each is one call into the neutral body.
- `_end_run(tool_context)`, which sets `actions.skip_summarization`; `end_run_when_ready(answer, AdkCall)` keeps its signature for `harness/scripted.py`.
- `PlanTool` (`planner/declaration.py`), `create_planner_agent`, `prepend_brief`.

## `_ask_beside_ask` on `response_calls()`

`PlannerCall` gains `response_calls() -> Sequence[ResponseCall]`, the `(name, call_id)` of each call of the model response that holds the call being served, in the order the model wrote them, and empty when the call has no id or no response holds it. `_ask_beside_ask` refuses an ask only when an earlier ask sits in that response, which is what the check did before the move. `AdkCall` reads the latest session event holding its call id; `PaiCall` reads the latest `ModelResponse` holding it.

`steps()` cannot carry this. An accepted ask's `ASK_ACCEPTED` response yields no step, so an accepted ask the user never answered and an ask of the later response stand next to each other, the same as two asks of one response, and the later one would be refused for the rest of the run. A `Step` has no response marker. A call with no id is in no response, so `response_calls()` is empty and the ask is not refused beside another.

Tests in `test_agent.py`: `test_an_ask_after_an_accepted_ask_nobody_answered_is_the_first_of_its_own_response` (the `steps()` check refused it, `response_calls()` accepts it), `test_an_ask_with_no_call_id_is_in_no_response_and_is_not_refused_beside_another`, and the existing `test_an_ask_after_the_first_ask_of_a_response_is_refused` with its four cases.
