## 2. The proposed slices against the code

1. Tool bodies on `PlannerCall`. Done in this tree (`tools.py` 535 lines, `source_reads.py` 1,079; `agent.py` 2,532 to 1,162). Confirmed; `scripted.py` and `revise` use `AdkCall`.

Touches `planner/agent.py` (about 200 lines of tool wrappers), `planner/declaration.py` (about 40), a new `planner/declarations.py` and a golden file. Gates: `tests/test_function_declarations.py`, `tests/planner/test_agent.py` (declaration tests at 2608, 3888, 14161-14258), `tests/planner/test_skills.py:77`, `tests/test_context_budget.py` with `context_baseline.json`. 1. Callbacks as neutral hooks. Confirmed, with two corrections: it also owns the synthetic responses and the public callback parameters, and a Pydantic AI hook for `before_tool` is needed (see 5). Moves about 300 lines of `planner_seam.py` to a new module, plus 80 of adapters. Gates: `tests/test_planner_seam.py` (6,492 lines), `tests/test_planner_entry_eval.py`, `tests/test_context_budget.py`. Ships on ADK alone.
1. Budget, cache, retries, thought filter as genai wrappers. Too large as one slice. `BoundedGemini` and `PrefixCachedGemini` also serve the orchestrator (`orchestrator/agent.py:361-434`), so the genai-level core must be added under them, not replace them. `bounded()` cannot mark a closing response with `custom_metadata`; genai's `GenerateContentResponse` has no such field, so the seam should read `TurnBudget.closed` (`planner_seam.py:1088` already does). Cut it in two. 4a: budget and cache core over genai responses; about 250 lines in `turn_budget.py` and `prefix_cache.py`; gates `tests/test_turn_budget.py`, `tests/test_prefix_cache.py`, `tests/telemetry/test_model_call_export.py`; ships on ADK alone but touches the orchestrator's model path. 4b: retries and the thought filter on the Pydantic AI side; nothing ships on ADK.
1. Translator reads neutral progress events. Confirmed, but it cannot replace the ADK reading on ADK alone: ADK's child events stream live, while `planning.py:258-269` relays the seam's progress only after the await. It ships as an additive second branch, inert until slice 6. The neutral event must carry what the translator reads: the call name before the tool runs (`studio_translate.py:1407`, from the model's response; `_track_tool_call` fires after the tool), the `propose_plan` response and the recorded plan (1410-1411). Gates: slice 3's tests plus the cross-path resume tests it adds.
1. Tracing parity. Confirmed; gates `tests/telemetry/test_model_call_export.py`, `test_studio_trace_export.py`. Nothing ships on ADK.
1. Live gate, flip, deletion. Confirmed; deletion also needs the consumers in the last table row.

Two further slices: (a) eval and scripted consumers (`evals/planner_entry` hooks, the two `evals/agents` builders, `harness/scripted.py`), needed before deletion and before any paired live run; (b) a test asserting every state key a tool body writes is in `_persist_durable`'s list, which ships on ADK alone before slice 6.

Parallel: after 1, slices 2, 3, 4a and (b) touch separate files and run together; 5 touches `planner_seam.py` with 3, so it follows 3. 6 needs 2, 3, 4a and 5. 7 and (a) run beside 6. 8 is last.

## 3. Declarations and instruction

Instruction: `planner_instruction(has_translator, has_skills, question_fixed)` (`planner/agent.py:488`) is a plain string, passed to `LlmAgent` at 1116. ADK then injects `{name}` state placeholders (`google/adk/flows/llm_flows/prompt/_instructions_utils.py:151-181`; a brace group that is not a valid state name, such as the `{kind:'place_level', ...}` at `agent.py:201`, is left alone) and may append `You are an agent. Your internal name is "dfo_planner".` (`_identity.py:38-43`, skipped for `single_turn`). The orchestrator strips both (`orchestrator/agent.py:338`). The planner strips neither.

Declarations: `ask_user_question` (`agent.py:814`), `get_skill`, `get_skill_file` (872-912) and `reject_plan` (993) use ADK's default declaration. `propose_plan` has eight variants: `translate` and `surface` choose the wrapper (`functools.wraps(propose_plan)`, 1002-1030), `question_fixed` chooses `_FIXED_ARGUMENTS`; `PlanTool` replaces each argument's description and compacts the schema (`declaration.py:247-271`).

"Neutral data, tested equal to ADK's" takes: a table of `name`, description and `parameters_json_schema` for all variants, written from `tool._get_declaration().model_dump(exclude_none=True)` once; a test per variant asserting equality with ADK's output; and a test that the instruction as ADK sends it (a recorded request) equals `planner_instruction`. Correct by construction: make the ADK tool a `FunctionTool` subclass whose `_get_declaration` returns the data, so one source feeds both paths and only the data needs a golden test.

## 4. Not determined

- Whether ADK sends the identity line for the planner node today; a recorded request would show it.
- Whether `revise` reads correctly with no planner ask events in the session: `call.py:119-150` accepts both ask shapes, but `prices_chosen` and the `response` steps were not traced.
- How Pydantic AI replays thought parts and signatures; `drop_thought_parts` and `_SKIP_THOUGHT_SIGNATURE` (`planner_seam.py:289`) depend on it.
- Where the span attributes in `turn_budget.py` land under Pydantic AI instrumentation.
- Sizes are estimates from line ranges, not diffs.
