# ADK runtime footprint of the harness orchestration layer

Pinned: `google-adk[db]==2.10.0` (`services/harness/pyproject.toml:17`). Read at HEAD; `graph/plan_done.py` and `orchestrator/agent.py` were read through `git show HEAD:`. Paths below are under `services/harness/src/` unless stated. "Inferred" marks a claim not read directly.

## Shape of the runtime

One `Workflow` named `dfo_analyst_graph` (`harness/graph/workflow.py:99-158`) with nine nodes: `seed`, `orchestrate`, `route`, `ask`, `plan_start`, `planner`, `approve`, `execute`, `plan_done`. `StudioRunner` wraps it in one `App` and one `Runner` (`harness/studio.py:550-551`). Each `/turn` creates a new ADK session `{conversation_id}#t{n}` (`studio_state.py:932-936`, `studio.py:563-577`). A paused turn resumes in a later HTTP request by calling `Runner.run_async` on the same session with a `function_response` message (`studio.py:1314-1325`, `1337-1340`). A second, per-conversation "ledger" session under app name `dfo_analyst_graph.ledger` holds all wire state (`studio_state.py:1316-1321`, `1334-1337`).

## 2. Behaviour a replacement must reproduce

Persistence and resume

1. A paused turn resumes in a later HTTP request, possibly on another Cloud Run instance, from state persisted in Postgres, without re-running completed nodes (`studio.py:1140-1340`; `studio_state.py:1-27`). ADK does this by replaying the workflow from START over the stored events and fast-forwarding any node that has a recorded run (memory `adk-resume-replays-from-start.md`).
1. Resume pairs the user's answer with the pause by a stable interrupt id (`"approve"`, `"clarify"`, and the planner's function-call id) and delivers it to the node as `ctx.resume_inputs[id]` (`planning.py:254`, `orchestrate.py:98`; `state.py:38-41`).
1. Interrupt ids repeat across rounds (an amended plan raises `approve` again), so a node tells a fresh entry from a resume by its own state flag (`awaiting_approve`, `ORCHESTRATOR_ASKED_KEY`) (`planning.py:253-263`, `orchestrate.py:99-110`).
1. A node added to the workflow must stay safe when a session paused before the deploy resumes. `seed` guards with `_turn_ran_before` (`seed.py:52-70`).
1. A pause can occur inside a child agent run started from a node (`planner` -> `ask_user`). The pause suspends the whole node, resumes by re-entering the node, and the child agent continues from its stored events (`planner_seam.py:1-60`, `planning.py:110-125`).
1. Session state written by tools and nodes persists as event `state_delta` and survives across `run_async` calls; a plain in-process write does not (`planner_seam.py:476-495, 634-693`).
1. Persisted keys and the app name stay readable: `AGENT_NAME="dfo_analyst_graph"`, the `orchestrator:*` keys (`state.py:36, 57-87`), the `studio:*` ledger keys (`studio_state.py:998-1013`), the `planner:plan` key, and `{conversation_id}#t{n}` session ids. A replacement either reads these or migrates them (see section 6).

Isolation

8. Orchestrator, planner and interrupt events never reach each other's model context. The planner sees its own full history (`include_contents="default"` on its branch), the orchestrator sees the turn without planner internals, and the `approve` payload (a whole compiled plan, possibly over 100k characters) reaches no model (`state.py:101-104`, `orchestrate.py:44-67`, `planner_seam.py:186-200`; memory `adk-unbranched-events-reach-every-agent.md`).
1. A hand-back to the orchestrator is a user message saved in the session so it stays in view after a later pause (`orchestrate.py:36-50`).
1. Two concurrent runs of one sub-agent in one invocation are told apart by branch, not invocation id (memory `adk-single-turn-run-boundary.md`).

Execution and streaming

11. `execute` runs a long task while relaying per-step progress as its own events, and cancels the task if the stream closes (`execute.py:140-200, 505-575`).
01. The `planner` node queues progress while it awaits a call that may pause, then relays it (`planning.py:110-190`).
01. A stream stop or client disconnect cancels the in-flight run cleanly through `aclosing` and `_unwind`, leaving a paused turn resumable (`studio.py:258-345, 430-446, 596-621`).
01. Text and thoughts stream as partial chunks, followed by one aggregated non-partial event. Pause frames use the non-partial event only (`studio.py:604`, `studio_translate.py:880-886`).
01. Events carry enough structure for the translator to emit frames: node name (`node_info.path`), route (`actions.route`), output dict, `custom_metadata` side channels (`STEP_PROGRESS_KEY`, `PLANNER_STARTED_KEY`, `ORCHESTRATOR_STATUS_KEY`), function calls and responses with author, and the state delta (`studio_translate.py:871, 1060-1106, 1631-1766`; `studio.py:415-427`).
01. A tool exception must not end the turn: the orchestrator answers the model with an error and goes on (`orchestrator/agent.py` HEAD :371, `orchestrator_tools.py:855-891`).

Concurrency and cancel

17. At most one instance streams a conversation. A lease with TTL, a heartbeat, a checkpoint and a cross-instance cancel signal sit on compare-and-swap writes to the ledger session (`studio_state.py:1-27, 1534-1560`). A replacement needs an equivalent compare-and-swap store.
01. A lost race ends in HTTP 409, not corruption: `StaleSessionError` on `/turn` claim, `/interrupt` first answer, `/composition` (`studio.py:968, 1239, 1412`); `AlreadyExistsError` on a duplicate turn-session create (`studio.py:894, 1031`).
01. Startup retries `prepare_tables()` for up to 120 s to survive IAM propagation (`server.py:183-245`; `README.md:209`).

## 3. Where ADK has cost us

- Replay from START. A turn paused before a node existed runs that node live on resume; `seed` needs `_turn_ran_before` (`graph/seed.py:52-70`). Memory: `adk-resume-replays-from-start.md`.
- `ctx.run_node` demands `rerun_on_resume=True` on the calling node, or ADK raises `ValueError` (`graph/workflow.py:53-59`).
- A `ctx.run_node` call cannot be wrapped in a task: `NodeInterruptedError` would sit on the task. So `planner` awaits directly and cannot relay progress live; reports queue and are dropped on a pause (`planning.py:110-190`).
- One `output` per node run. Progress goes on `custom_metadata`, never `output` (`planning.py:77-86`, `execute.py:203-213`). An `Event(output=None)` records nothing, so `orchestrate` emits `""` to keep resume replayable (`orchestrate.py:71-76`).
- Branch semantics. ADK treats an event with no branch as belonging to every branch, and quotes it into other agents' prompts. Fixes: stamp every planner event (`override_branch`, checked by `_check_branches`, `planner_seam.py:186-200, 1304-1340`), stamp interrupts with a dead branch `dfo_interrupts` (`state.py:101-111`), author the hand-back as `user` on the agent's branch and clear the branch with `branch=""` on the status event, and flip `ctx.event_author` temporarily (`orchestrate.py:44-67`).
- Node-mode agents default to `single_turn` with `include_contents='none'`, which drops the brief; pinned to `"default"` on both agents (`planner/agent.py:1472-1484`, orchestrator HEAD :372-376).
- Writes through `ctx.state` queue as a delta on the node's next event and can overwrite fresher child writes. The seam writes `ctx.session.state` directly and copies back with `_persist_durable` (`planner_seam.py:476-495, 634-693`).
- A paused long-running tool call produces no response event, so nothing written in that call survives; the seam rebuilds candidates from the call event's `args` (`planner/agent.py:674-690`).
- Tool arguments arrive unvalidated, and an exception in a tool body fails the node: every orchestrator tool goes through `_validated_arguments` (`orchestrator_tools.py:855-891`; memory `adk-tool-args-unvalidated.md`; `submission/service.py:279` repeats the point).
- `GraphState` validates writes of undeclared keys, so the `orchestrator:` prefix is used to skip validation (`state.py:54-56`).
- A paused interrupt event is an ADK function call; the pause frame is built from the non-partial event only, because chunks name calls the session may never hold (`studio_translate.py:880-886`).
- The session service has no compare-and-swap API of its own, so the harness uses `StaleSessionError` on `append_event` as one, plus `num_recent_events=0` reads to avoid loading event history (`studio_state.py:1374-1385, 1409-1416`).
- DB schema churn: ADK 2.10 added `idx_events_app_user_session_ts_id`; `prepare_tables()` builds it with a blocking `CREATE INDEX`. README documents a manual out-of-band build and a later drop of the old index (`README.md:211-218`).
- Cloud SQL requires injecting an async engine with `async_creator` because the service accepts a URL or an engine only (`session_store.py:7-22, 121-162`). The service's `close()` does not dispose an injected engine (`session_store.py:50-57`).
- Test-only: sqlite `DatabaseSessionService` needs WAL mode or a cancelled turn's reader blocks the end-of-segment write for 5 s (`tests/sqlite_session.py:1-12`).
- Private imports break on upgrade (10 source and 3 test sites above).

## 4. What ADK gives us that we would rebuild

- Graph execution: named-route edges, cycles, fan-in to one node, per-node output recording.
- Durable run state: every event persisted with `node_info`, `branch`, `state_delta`, and a replay engine that fast-forwards completed nodes (inferred from memory `adk-resume-replays-from-start.md`; engine in `google/adk/workflow/_workflow.py`, `utils/_replay_interceptor.py`, not re-read here).
- Pause and resume as a first-class event pair (`adk_request_input` call and response), with id matching (`utils/_rehydration_utils._reconstruct_node_states`, per memory note).
- Session storage schema and service: tables `sessions`, `events`, `app_states`, `user_states`, `adk_internal_metadata` (`sessions/schemas/v1.py:56-267`), optimistic concurrency by `update_time` (`database_session_service.py:907-977`), in-memory twin for tests.
- State prefix scoping (`app:`/`user:`/`temp:`) and `state_delta` merge on `append_event` (inferred; `deep_merge_dicts` is cited at `translator/discovery.py:790` as ADK's merge of concurrent tool deltas).
- Streaming partial/aggregated model events and function-call event construction.
- Tool-loop semantics: parallel tool calls, long-running tools, `ToolContext`, callbacks.
- OTel spans per model call, nested under our turn span (`docs/architecture.md:197-210`).
- ADK eval framework (`docs/architecture.md:220`; the harness evals run on it; other agent's scope).

## 6. Persisted format a replacement must read or migrate

ADK's v1 tables (`google/adk/sessions/schemas/v1.py`): `sessions(app_name, user_id, id, state JSON, create_time, update_time)`; `events(id, app_name, user_id, session_id, invocation_id, timestamp, event_data JSON)` where `event_data` is the full `Event.model_dump(exclude_none, mode="json")` (`v1.py:156-236`); `app_states`, `user_states`, `adk_internal_metadata`. Two session families share them: ledger sessions (`app_name = dfo_analyst_graph.ledger`, `session_id = conversation_id`, state keys `studio:*`) and turn sessions (`app_name = dfo_analyst_graph`, `session_id = {cid}#t{n}`, state keys `orchestrator:*`, `planner:*`, `plan`, `surface`, `canvas_digest`, `seeds`, `awaiting_approve`, `replans`, plus events holding node paths and `adk_request_input` calls). Ledger state is the one that matters for continuity (composition manifests, turn records, pending interrupts). A paused turn session is only resumable by ADK's replay engine, so a replacement could drop in-flight pauses at cutover (a user re-asks) but must carry ledger state (inferred: no code reads old turn sessions after their turn closes except `_turn_specs`, `studio_state.py:1425-1442`).
